# Cross-platform audio: backends and API shape for the final state

## 1. Question

What backends and what API shape should SpartanGraphics' audio artifacts (`audio-core` plus `audio-desktop`, `audio-android`, `audio-web`) have in the final state, covering playback control, WAV/OGG/MP3, buses with per-category volume, streamed music with crossfade, positional 2D audio from a game-set listener, and room for DSP and ducking later? A good answer says what the 1.0-frozen contract looks like, which desktop backend to use and when, what the Android and web backends are, and in what order they land.

## 2. Bottom line

- **Freeze a mid-level contract, not a thin PCM-sink one and not a "play this file" one.** App-facing: an `AudioEngine` with `Clip` (fully decoded, short), `StreamSource` (music), a `Voice` handle (stop/pause/loop/gain/pan/rate/position), and a bus tree. Backend SPI: voices, buses (gain plus parent), a listener-agnostic `gain + pan` per voice, suspend/resume, and a capability set. Every platform can implement this natively: Web Audio's graph is a bus graph, OpenAL and SoundPool are voice-only and emulate buses by gain multiplication, and a software mixer can do both.
- **Keep policy in common Kotlin, not in backends.** Bus gain propagation, voice limits and priority and stealing, crossfade/fade ramps, ducking, and 2D positional gain and pan (attenuation model plus equal-power pan) are all computed in `audio-core`. The backend only receives resulting per-voice gain and pan. This gives identical behaviour on all three platforms, removes any dependency on `PannerNode`, OpenAL positioning, or Android panning (SoundPool has only `setVolume(left, right)`), and keeps the SPI small. The cost is control-rate (about 60 Hz) parameter updates, so gain changes need ramping or smoothing in the backend.
- **Desktop backend: keep the JLayer port for 0.1.0 as planned, then move the engine to OpenAL Soft through LWJGL** (with `stb_vorbis` for OGG and JLayer retained for MP3 decoding) when the playback-control/mixing phase lands. The choice is cheap to change while the SPI is still 0.x; the contract shape is what is expensive. Reject miniaudio for now: LWJGL has no binding, so it means hand-rolled JNI, and Vorbis is not built in.
- **Android: `SoundPool` for clips plus `MediaPlayer` for music** (the libGDX recipe, proven for a decade), with buses emulated. Plan an `AudioTrack`/Oboe software-mixer backend later, only if real DSP effects on Android are scheduled. **Web: Web Audio graph for everything**: `AudioBuffer` for clips, `MediaElementAudioSourceNode` over an `HTMLAudioElement` for streamed music, one `GainNode` per bus, `StereoPannerNode` per voice.
- **`AssetSource` needs three audio-driven capabilities that a "name to bytes" read does not give:** an async read; a sequential stream (with optional length and seek) for music; and a platform locator escape hatch (a URL on web, an asset file descriptor on Android) because `HTMLAudioElement` and `MediaPlayer` want to do their own I/O. Decoding a 3-minute stereo track fully on web costs about 69 MB of float32, so "bytes only" is not viable for music.
- **Lifecycle and the web autoplay lock belong in the contract.** The engine has an observable state (`Locked`/`Running`/`Suspended`/`Interrupted`), `suspend()`/`resume()`, and an interruption policy parameter. Android audio focus and web `visibilitychange`/`interrupted` are handled inside the backends, not by the game.
- **Landing order:** 0.1.0 thin port; then the full engine model (voices, buses, streaming, spatial, lifecycle) and the OpenAL backend in one 0.x release; then `audio-android` and `audio-web` written once against that SPI, alongside the graphics Android/web backends; then 1.0 freezes. Effects and sidechain DSP stay Experimental after 1.0, and ducking ships earlier as a bus-gain rule that needs no DSP.

## 3. Findings

Evidence tiers: **consensus** (standard or several independent sources), **practice** (what mature libraries visibly do), **opinion** (single source).

### 3.1 Platform capabilities

1. **Web: autoplay lock.** A Web Audio `AudioContext` created outside a user gesture starts `suspended` and must be `resume()`d from a user-triggered handler; the spec states a context may only go suspended to running if it is "allowed to start", i.e. the page has sticky activation. *Tier: consensus (MDN plus W3C spec).* [MDN best practices](https://developer.mozilla.org/en-US/docs/Web/API/Web_Audio_API/Best_practices), [Web Audio spec](https://webaudio.github.io/web-audio-api/#BaseAudioContext-state)
2. **Web: a fourth state, `interrupted`.** The spec lists `suspended`, `running`, `closed`, `interrupted`. On iOS Safari, leaving the page moves the context to `interrupted` and it needs resuming. WebKit bug reports show contexts stuck `interrupted`, or `running` but silent after another app made noise; reporters' workaround is `suspend()` then `resume()` on `visibilitychange`. *Tier: spec for the state; bug-report anecdotes for the workaround (practice, not official guidance).* [spec](https://webaudio.github.io/web-audio-api/#BaseAudioContext-state), [WebKit 276016](https://bugs.webkit.org/show_bug.cgi?id=276016), [WebKit 283419](https://bugs.webkit.org/show_bug.cgi?id=283419), [WebKit 273511](https://bugs.webkit.org/show_bug.cgi?id=273511)
3. **Web: decode and streaming.** `decodeAudioData` decodes any format the `<audio>` element supports into an `AudioBuffer`, resampled to the context rate. MDN's advice: buffers for short sample-like sounds, a media element for full-length tracks (media elements stream; start once the browser expects to finish loading). A media element is routed into the graph with `createMediaElementSource`, so streamed music can sit on the same gain buses. *Tier: consensus.* [MDN](https://developer.mozilla.org/en-US/docs/Web/API/Web_Audio_API/Best_practices), [spec](https://webaudio.github.io/web-audio-api/#BaseAudioContext-state). (The `createMediaElementSource` detail was stated by the fetch tool as general knowledge, not quoted from the page.)
4. **Web: latency knobs.** `latencyHint` is `"interactive"` (default), `"balanced"` or `"playback"`; `baseLatency` is about 5.8 ms at 44.1 kHz with a 128-frame quantum; `outputLatency` is an estimate and can change while running. *Tier: spec.* [spec](https://webaudio.github.io/web-audio-api/#BaseAudioContext-state)
5. **Web: spatial primitives.** `PannerNode` has `distanceModel` `linear`/`inverse`(default)/`exponential`, `refDistance`, `rolloffFactor`, `maxDistance`, `panningModel` `equalpower`(default)/`HRTF`; the listener is `BaseAudioContext.listener`. *Tier: spec.* [MDN PannerNode](https://developer.mozilla.org/en-US/docs/Web/API/PannerNode)
6. **Formats on web.** MP3: all major browsers. Vorbis in `<audio>`: Chrome 4, Firefox 3.5, historically not Safari. Apple's Safari 18.4 release notes (31 March 2025) say "Added support for Ogg Opus and Ogg Vorbis on macOS Sequoia 15.4, iOS 18.4, iPadOS 18.4, and visionOS 2.4". Caniuse marks Safari desktop "supported" from 18.4 and iOS from 18.4 (partial before). One developer reports Ogg Opus is still "incomplete, buggy" in 18.4, but the specifics were MediaRecorder, not playback or `decodeAudioData`. *Tier: vendor release notes plus caniuse (good) for support; one blog for "buggy" (opinion, and about recording).* [MDN codecs](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Formats/Audio_codecs), [Safari 18.4 notes](https://developer.apple.com/documentation/safari-release-notes/safari-18_4-release-notes.md), [caniuse](https://caniuse.com/ogg-vorbis), [frequal.com](https://frequal.com/java/OggOpusStillNotWorkingInSafari18_4.html)
7. **Android: API choice.** Google's NDK guide: OpenSL ES is "not recommended for new designs"; target Oboe (or AAudio). Oboe uses AAudio on API 27+ and OpenSL ES below. Low-latency checklist: low-latency performance mode, exclusive sharing, device-native rate (usually 48 kHz), a data callback, `Usage::Game`. OboeTester round-trip numbers: about 20 ms following all advice; 205 ms without low-latency mode; 160 ms at 44.1 kHz through AAudio's own conversion. Callbacks must never allocate, lock, or do I/O. *Tier: vendor docs.* [NDK audio](https://developer.android.com/ndk/guides/audio), [low-latency](https://developer.android.com/games/sdk/oboe/low-latency-audio)
8. **Android: SoundPool and MediaPlayer are what libGDX actually uses.** `DefaultAndroidAudio` builds a `SoundPool` with game usage plus sonification content type and `maxSimultaneousSounds` streams, uses `MediaPlayer` for `Music` (game usage, music content type), loads internal files through `AssetFileDescriptor`, and on pause iterates music pausing each and calls `soundPool.autoPause()`, mirrored on resume. libGDX docs: an Android `Sound` cannot exceed 1 MB of decoded PCM (use `Music` for larger); `Music` is heavy on Android, so keep at most about 10 loaded and 1 to 2 playing; MP3 has trouble with seamless looping; OGG does not work on RoboVM or Safari (GWT). *Tier: practice (mature library source).* [DefaultAndroidAudio](https://raw.githubusercontent.com/libgdx/libgdx/master/backends/gdx-backend-android/src/com/badlogic/gdx/backends/android/DefaultAndroidAudio.java), [libGDX Sound](https://libgdx.com/wiki/audio/sound-effects), [libGDX Music](https://libgdx.com/wiki/audio/streaming-music)
9. **Android: audio focus is mandatory behaviour for a game.** Request focus before playing, respond to loss (permanent loss: pause; transient: pause and resume on gain; can-duck: lower volume), abandon when done. From Android 12, an app using `USAGE_GAME`/`USAGE_MEDIA` focus is faded out by the system when another app takes focus and "shouldn't play audio after losing focus"; from Android 15 a focus request fails unless the app is top or runs a foreground service. *Tier: vendor docs.* [Audio focus](https://developer.android.com/media/optimize/audio-focus)
10. **Desktop JVM: javax.sound has no MP3/OGG out of the box.** The JDK documents WAV/AIFF/AU as the standard formats and extension via service providers; MP3 and Ogg need third-party SPIs. (The fetch tool added "the JDK doesn't ship MP3 or Ogg codecs" as general knowledge; it is true but not quoted from the page.) *Tier: consensus.* [Oracle Java Sound tutorial](https://docs.oracle.com/javase/tutorial/sound/converters.html)
11. **LWJGL audio bindings.** The `lwjgl3` repo's module list has `openal`, `stb` (which contains `stb_vorbis`), `opus`, `fmod`; it has no `miniaudio` and no `dr_libs` module. LWJGL 3.3.0 updated OpenAL Soft to 1.21.1 and stb_vorbis to 1.22 and added opusfile. So OpenAL plus OGG are covered; MP3 decoding is not (JLayer stays). *Tier: repo listing (the fetch said the list may be truncated, but it was a complete-looking alphabetical set).* [lwjgl3/modules](https://github.com/LWJGL/lwjgl3/tree/master/modules/lwjgl), [3.3.0 notes](https://github.com/LWJGL/lwjgl3/blob/master/doc/notes/3.3.0.md)
12. **OpenAL Soft.** LGPL-2+ licensed; EFX extension provides air absorption, occlusion and environmental reverb; default distance model is inverse-distance clamped (reference distance default 1.0, `AL_SOURCE_RELATIVE` makes source position listener-relative). *Tier: project README plus API reference.* [openal-soft README](https://github.com/kcat/openal-soft/blob/master/README.md), search results quoting an OpenAL lecture and jMonkeyEngine's `AL` javadoc (not the primary spec; see Gaps).
13. **miniaudio.** Engine (`ma_engine`) plus per-playback `ma_sound`, sound groups with independent volume, spatialization with listener/cones/four attenuation models (none/inverse/linear/exponential) and Doppler, no HRTF; `MA_SOUND_FLAG_STREAM` streams (about 2 s in memory), `MA_SOUND_FLAG_DECODE`/`ASYNC` pre-decode and load async; resource manager ref-counts loaded sounds; built-in WAV/FLAC/MP3 but Vorbis only through external backends; Android uses AAudio with an OpenSL ES fallback; web via Web Audio through Emscripten. *Tier: library manual.* [miniaudio manual](https://miniaud.io/docs/manual/index.html)

### 3.2 Design patterns in comparable libraries

14. **Clip vs stream split is universal.** libGDX `Sound` vs `Music`; raylib `Sound` vs `Music`; Web Audio buffer vs media element; Android SoundPool vs MediaPlayer. miniaudio folds both into one `ma_sound` with a stream flag. *Tier: practice.* sources above plus [raudio.c](https://github.com/raysan5/raylib/blob/master/src/raudio.c).
15. **Handle per playback.** libGDX `Sound.play()` returns a `long` id used with `stop(id)`, `setPan(id, pan, volume)`, `setLooping(id, true)`, `setPitch(id, ...)`. Android `SoundPool.play` returns a stream id. miniaudio's `ma_sound` is a per-instance object. *Tier: practice.* [libGDX Sound](https://libgdx.com/wiki/audio/sound-effects)
16. **Voice limits live in the library on OpenAL.** libGDX's OpenAL backend defaults to 16 simultaneous sources, pools them as idle/active, returns -1 when none is free, and needs an `update()` call from the owner to feed streaming `Music`. raylib's raudio has a 16-channel default and a 4096-sample music buffer sized for a 60 Hz refill. *Tier: practice.* [OpenALLwjgl3Audio](https://raw.githubusercontent.com/libgdx/libgdx/master/backends/gdx-backend-lwjgl3/src/com/badlogic/gdx/backends/lwjgl3/audio/OpenALLwjgl3Audio.java), [raudio.c](https://github.com/raysan5/raylib/blob/master/src/raudio.c)
17. **Bus model reference: Godot.** Master bus at left, each bus sends to a bus on its left (no cycles by construction), any number of ordered effects per bus, volume in dB, players pick a bus by name, and renaming a bus silently reroutes its players to Master; the layout is a saved resource. *Tier: engine docs.* [Godot audio buses](https://docs.godotengine.org/en/stable/tutorials/audio/audio_buses.html)
18. **Bevy and Kira.** Bevy's built-in audio puts a `SpatialListener` on an entity and enables spatial per sound (`PlaybackSettings::with_spatial(true)`), with a `SpatialScale` (its 2D example uses 100 pixels per audio unit) and a `GlobalVolume` resource. `bevy_kira_audio` uses channels instead of buses and has limited spatial support. Kira itself offers tweens, a mixer with sub-tracks and effects, and a clock system; on wasm it cannot stream. *Tier: practice (Bevy docs/examples, Kira README).* [bevy_audio](https://docs.rs/bevy_audio), [Bevy 2D spatial example](https://bevy.org/examples/audio/spatial-audio-2d/), [bevy_kira_audio](https://docs.rs/bevy_kira_audio), [Kira](https://github.com/tesselode/kira)
19. **Kotlin Multiplatform state of the art for web audio.** Kotlin's stdlib exposes `org.w3c.dom.Audio` (`HTMLAudioElement`) but I found no `AudioContext` in stdlib; the available wrappers are young (`io.gitlab.casperix:webaudio` 0.1.0, Nov 2024; others are whole players, e.g. `soundscape-player`, which uses Web Audio on WASM, Media3 ExoPlayer on Android, JavaSound on desktop). So `audio-web` will carry its own small `external` declarations. *Tier: thin (search listing only).* [klibs.io search results](https://klibs.io/package/io.gitlab.casperix/webaudio), [stdlib Audio](https://kotlinlang.org/api/core/2.0/kotlin-stdlib/org.w3c.dom/-audio/-audio.html)

### 3.3 This repo today

20. `SoundPlayer` (the monolith) re-opens the classpath resource, creates a JLayer `Player`, and decodes the MP3 on a cached-thread-pool thread on every `play(name)`; there is no handle, no stop, no volume, no loop, no preload. The client's new sound tree (`ambient/` loops, `atmosphere/`, `combat/`, `ui/`, one-shot stingers) is an MP3-only library. `ambient/background_chirping_birds.mp3` and `background_wind.mp3` are loops, and MP3 is the format libGDX warns is poor for seamless loops (finding 8). *Tier: read from the repo.* `D:\Documents\Programming\GameGraphics\src\main\kotlin\com\spartanlabs\audio\SoundPlayer.kt`

| Project | Desktop | Android | Web | Notes |
|---|---|---|---|---|

Concrete signatures worth copying: libGDX `Sound.play(volume): Long`, `setPan(id, pan, volume)`, `setLooping(id, Boolean)`; Android `SoundPool.Builder().setMaxStreams(n).setAudioAttributes(...)`; Web `new PannerNode(ctx, { distanceModel: "inverse", refDistance, rolloffFactor, maxDistance })`; miniaudio's attenuation set (none/inverse/linear/exponential) is the intersection every backend can compute.

## 5. Pitfalls and regrets

- **Stale handles.** libGDX and SoundPool hand out numeric ids that outlive the voice; a stolen or finished voice's id may be reused. Use generation-checked handles that become no-ops.
- **String-addressed buses.** Godot's own docs warn renaming a bus reroutes its players to Master. Use bus handles created from a layout, not bare strings at every call site.
- **MP3 loops.** Encoder padding makes seamless loops impossible (libGDX docs). Loop sources must be OGG or WAV; the asset pipeline (Gradle plugin) should flag or transcode them.
- **Decoding on first play.** The monolith decodes at click time. Clip loading must be explicit and async, and `play` must be a non-blocking enqueue.
- **Callbacks on the audio thread.** Oboe's rules (no locks, no allocation, no I/O) mean user callbacks must never run there; events should be queued and dispatched on the game thread (engine `update()`/supplied dispatcher), as libGDX's `update()` model does.
- **Web unlock.** Starting music before any gesture silently produces nothing; and on iOS Safari the context can go `interrupted` or silent-`running`. The engine needs a state, retry on gesture, and a deferred-start voice state.
- **Android 12/15 focus rules.** Playing after losing focus is blocked by the system, and an unfocused/background app can't even request focus on 15. Lifecycle pause is not optional.
- **Control-rate gain changes click.** Computing positional gain in common code at 60 Hz means steps; backends must smooth (`setTargetAtTime` on Web, short ramps elsewhere).
- **Spatialising stereo files.** OpenAL positional audio generally needs mono sources and libGDX notes `setPan` does not work on stereo sounds (GWT). Document "positional sounds should be mono"; for stereo assets, apply balance only. (OpenAL's mono-only rule is from memory, see Gaps.)
- **License stacking.** OpenAL Soft is LGPL; JLayer is, as far as I know, LGPL too. Both load dynamically as separate native lib/jar, but an Apache-2.0 library that pulls them transitively should say so in the README/NOTICE and let apps override. Needs a check before publishing.

## 6. Recommendation for this repo

### 6.1 The contract (what 1.0 freezes)

Frozen at 1.0, sorted by the user's tiers:

**Stable Core (`audio-core`, app-facing).**
- `AudioEngine`: `suspend fun loadClip(name): Result<Clip>`, `suspend fun openStream(name): Result<StreamSource>`, `fun play(clip|stream, PlayParams): Voice` (non-suspending, non-blocking, never throws), `bus(...)`, `listener`, `state`, `suspend()`/`resume()`, `close()`. A convenience `play(name)` that loads-and-caches keeps `SoundPlayer` parity.
- `Voice`: generation-checked handle; `stop()`, `pause()`, `resume()`, `loop`, `gain`, `pan`, `rate`, `position`, `fade(to, duration)`, `state`. A stale handle is a no-op.
- `AudioBus`: tree, `gain` (linear; dB helpers), `mute`. Created from a layout (`master` -> `music`, `sfx` -> `ui`/`combat`/`ambient`), handles not strings.
- `Listener` (x, y, and a reserved z default 0), per-voice emitter position, `SpatialScale`, and an `AttenuationModel` strategy with default inverse-clamped (`refDistance`, `maxDistance`, `rolloff`).
- Policy parameters with defaults: `VoiceLimitPolicy` (global and per-bus caps, priority, steal-oldest/quietest), `InterruptionPolicy`, `UnlockPolicy` (auto-unlock on first input, pending-start voices), `FormatPreference`.
- A `Jukebox`/`MusicPlayer` helper built purely on `Voice` fades: `crossfadeTo(track, duration)`. Ducking as a `Ducker(trigger bus -> target bus, amount, attack, release)` rule over bus gains.

**Backend SPI (`@SupportedExtension` after 1.0, with a documented example backend).**
- `AudioBackend`: `capabilities: Set<AudioCapability>`, `canDecode(format)`, `createClip(bytes|decodedPcm)`, `createStream(source)`, `createBus(parent)`, `startVoice(...)`, voice/bus parameter setters accepting `rampTo(value, duration)` where supported, `suspend()`/`resume()`, an event queue the engine polls, `close()`.
- Voice parameter set is exactly: gain, pan (-1..1), rate, loop flag (with optional loop points), position, state. Positional maths is not in the SPI.
- A capability set (not extra mandatory methods) is how new features arrive after 1.0, plus building the library with default-method-compatible interface compilation so adding a defaulted member doesn't break third-party backends. (The Kotlin mechanics belong to the idiomatic-kotlin and backend-contract researchers.)

**Reserved, not frozen: Experimental behind `@RequiresOptIn`.** `AudioBus.effects` plus an open `Effect` interface (low-pass, high-pass, reverb, delay, compressor/sidechain). Backends advertise `BusEffects`. Web Audio and a software mixer can do this; OpenAL (EFX aux sends) and SoundPool/MediaPlayer can only approximate it. Promote once a real consumer exists.

### 6.2 Backends

| Platform | Clips | Streaming music | Buses | Positional | Decoders |
|---|---|---|---|---|---|
| Desktop (final) | OpenAL buffers, pre-decoded | OpenAL buffer queue fed by a decode thread | emulated (gain multiply in common) | `gain + pan` from common; pan via source offset or stereo mix | WAV (small parser), OGG (`stb_vorbis`), MP3 (JLayer) |
| Desktop (0.1.0) | JLayer decode to PCM, play via a custom `AudioDevice`/`SourceDataLine` | same, one thread each | none | none | MP3 only |
| Android | `SoundPool` | `MediaPlayer` (asset file descriptor) | emulated | `setVolume(left, right)` from common pan | platform decoders (MP3/OGG/WAV; support table not re-verified) |
| Web | `decodeAudioData` to `AudioBuffer` | `HTMLAudioElement` + `createMediaElementSource` | real `GainNode` per bus | `StereoPannerNode` per voice; common computes gain/pan | browser-native; OGG needs Safari 18.4+ |

Reasoning for **OpenAL, not "keep JLayer/JavaSound":** the game client already ships LWJGL natives, so marginal packaging cost is near zero (the baseline plan already puts natives on the app, not the library); libGDX's decade-old desktop backend proves the model and its 16-source pooling, device-switch polling and manual music streaming are precedent; `stb_vorbis` brings OGG with no new dependency; EFX and native positional support cover the unscheduled 3D and DSP tracks on desktop without new dependencies. JavaSound plus a hand-written Kotlin mixer would also work and avoids natives, but needs a self-made mixer on the audio thread and a pure-Java Vorbis decoder I could not verify. Keep a no-native JavaSound fallback only if a consumer asks. This choice is internal until 1.0 and cheap to flip.

Reasoning for **rejecting the obvious miniaudio-everywhere option:** it has the best cross-platform engine (engine, groups, spatialization, AAudio, Web Audio), but it is not in LWJGL, would need a JNI/FFM layer built and shipped for every ABI, and its engine model would leak into the contract. Treat it as a possible third-party backend that proves the SPI is open.

Reasoning for **SoundPool + MediaPlayer on Android** rather than Oboe first: no NDK or C++ in a KMP publish, proven recipe, and effects are unscheduled. Reasoning for the **escape hatch**: if Android DSP or tight timing ever needs it, add an `AudioTrack`/Oboe PCM-mixer backend behind the same SPI; the common-owned policy layer means no contract change.

### 6.3 What audio needs from `AssetSource`

(Design belongs to the asset-pipeline researcher; these are audio's requirements.)
1. **Async read** (`suspend`, `Result`) of whole bytes, for clips.
2. **Sequential stream** (`Source`-like, with optional known length and `seek`/reset) for music. Required on desktop for decode-while-playing.
3. **Locator escape hatch**: on web a URL (an `HTMLAudioElement` streams its own range requests), on Android an asset file descriptor (`MediaPlayer`/`SoundPool` take one). Without this, audio-web would have to download a whole track and decode it (about 69 MB float32 for 3 minutes stereo at 48 kHz, my arithmetic) or push bytes through Media Source Extensions.
4. **Cheap existence/size/format probing** so `FormatPreference` can choose `.ogg` vs `.mp3` per platform before loading.

### 6.4 Landing order

1. **0.1.0 (G6):** `audio-core` with the final names for the narrow subset (`AudioEngine`, `Clip`, a `Voice` with at least `stop`), `audio-desktop` JLayer port, clips decoded once. Marked pre-1.0 churn is acceptable per the user's decision 2.
2. **A 0.x "mix" release:** voices, buses, voice limits, fades/crossfade, streaming, spatial (common code), lifecycle and state, and the desktop OpenAL backend. WAV and OGG arrive here. This is the release that settles the SPI.
3. **With the Android and web graphics backends:** `audio-android` and `audio-web`, written once against the settled SPI, with the audio sample proven in the per-platform sample apps. This is before 1.0 because the audio backend is a frozen contract (decision 4) and two extra implementations are the only real test that it is not desktop-shaped.
4. **1.0:** freeze Stable Core plus SPI; SPI graduates to `@SupportedExtension` with an example backend (the Web Audio backend is the natural readable one).
5. **Post-1.0:** Experimental bus effects and sidechain DSP; a possible `AudioTrack`/Oboe mixer for Android; unscheduled gamepad-style items (audio DSP and ducking sidechain) fit the reserved seam.

For the client specifically: convert the two `ambient/` loops (and any music) to OGG during the mix release, keep short UI/combat clips as-is (MP3 is fine for one-shots), and add categories `ui`, `combat`, `ambient`, `atmosphere` as the first bus layout.

## 7. Gaps

- **Firecrawl was not used** (low credits); research used WebSearch/WebFetch only. My session also hit a usage limit before I could check the Android supported-media-formats page, so **Android codec support (MP3/OGG/WAV) and API levels are from memory, not verified.** Same for the SoundPool official limits (I relied on libGDX's statement of the 1 MB decoded limit).
- **Not verified:** OpenAL mono-only spatialisation; OpenAL Soft's default source count; the list of EFX effects; JLayer's licence and its `AudioDevice`/`Decoder` plug-in surface (I know them from the library, but did not re-read them this session); that Godot's web build uses Web Audio worklets.
- **Not found:** any measured output-latency number for JavaSound vs OpenAL on Windows; I deliberately make no latency claim for the desktop choice. The only latency figures here are Android's (round-trip, from Google) and Web Audio's `baseLatency` formula.
- **OpenAL default distance model** and `AL_SOURCE_RELATIVE` came from a lecture and jMonkeyEngine javadoc, not the Creative/Khronos spec.
